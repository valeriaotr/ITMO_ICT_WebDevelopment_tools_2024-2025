LR1. Сервис управления хакатонами

Документация лабораторной работы № 1 по разработке REST-сервиса для управления хакатонами. В этом проекте мы реализовали бэкенд на FastAPI + SQLModel, обеспечивающий полную цепочку:

  1. Регистрация и аутентификация пользователей
  2. Создание и управление хакатонами
  3. Формирование команд участников
  4. Создание и решение задач (problems & submissions)
  5. Хранение и выдача результатов

1. Архитектура и стек технологий

  • FastAPI — асинхронный веб-фреймворк на Python
  • SQLModel (на базе SQLAlchemy) — декларативные ORM-модели + pydantic-схемы
  • PostgreSQL — реляционная база данных
  • Alembic — управление версиями схемы БД (миграции)
  • JWT — токены для авторизации API
  • Uvicorn — ASGI-сервер для запуска приложения

Структура проекта:

  • main.py
  • Все эндпоинты приложения
  • models.py
  • QLModel-модели + DTO-схемы
  • connection.py
  • Инициализация DB + сессий
  • migrations/
  • Alembic-миграции

2. Схема данных и связи

2.1. Таблицы и модели

# models.py

class User(SQLModel, table=True):
    id: int
    username: str
    email: str
    hashed_password: str
    teams: List[Team]            # M-to-M через TeamMemberLink
    submissions: List[Submission]

class Hackathon(SQLModel, table=True):
    id: int
    title: str
    description: Optional[str]
    start_date: Optional[str]
    end_date: Optional[str]
    teams: List[Team]            # 1-to-N
    problems: List[Problem]      # 1-to-N

class Team(SQLModel, table=True):
    id: int
    name: str
    hackathon_id: int            # FK → Hackathon.id
    members: List[User]          # M-to-M через TeamMemberLink
    submissions: List[Submission]# 1-to-N

class Problem(SQLModel, table=True):
    id: int
    title: str
    description: Optional[str]
    hackathon_id: int            # FK → Hackathon.id
    submissions: List[Submission]# 1-to-N

class Submission(SQLModel, table=True):
    id: int
    user_id: int                 # FK → User.id
    team_id: int                 # FK → Team.id
    hackathon_id: int            # FK → Hackathon.id
    problem_id: int              # FK → Problem.id
    timestamp: Optional[str]
    result: Optional[str]

3. Аутентификация и пользователи

3.1. Регистрация

•   POST /auth/register
•   Параметры (form/query):
•   username: str
•   email: str
•   password: str
•   Возвращает: { msg: "Registered" }

3.2. Логин

•   POST /auth/login
•   Параметры:
•   username: str
•   password: str
•   Возвращает: { access_token: "<JWT>" }

3.3. Работа с токеном

  • Все защищённые роуты требуют заголовок
Authorization: Bearer <JWT>

4. CRUD для основных сущностей

4.1. Хакатоны

Метод Путь Тело запроса (JSON) Описание
POST /hackathons { title, description?, start_date?, end_date? } Создать новый хакатон
GET /hackathons — Получить список всех хакатонов
GET /hackathons/{id} — Получить детали конкретного хакатона
PATCH /hackathons/{id} Любые из полей создания Обновить хакатон
DELETE /hackathons/{id} — Удалить хакатон

4.2. Команды

Метод Путь Тело запроса (JSON) Описание
POST /teams { name, hackathon_id, members: [user_id,…] } Создать команду
GET /teams — Получить список всех команд
GET /teams/{id} — Получить детали конкретной команды
PATCH /teams/{id} { name?, hackathon_id?, members? } Обновить команду
DELETE /teams/{id} — Удалить команду

4.3. Задачи (Problems)

Метод Путь Тело запроса (JSON) Описание
POST /problems { title, description?, hackathon_id } Создать задачу
GET /problems — Получить список всех задач
GET /problems/{id} — Получить детали конкретной задачи
PATCH /problems/{id} { title?, description?, hackathon_id? } Обновить задачу
DELETE /problems/{id} — Удалить задачу

4.4. Решения (Submissions)

Метод Путь Тело запроса (JSON) Описание
POST /submissions { user_id, team_id, hackathon_id, problem_id, timestamp?, result? } Отправить решение
GET /submissions — Получить список решений
GET /submissions/{id} — Получить детали решения
PATCH /submissions/{id} Любые поля создания Обновить решение
DELETE /submissions/{id} — Удалить решение

5. Примеры использования

5.1. Регистрация и получение токена

curl -X POST http://127.0.0.1:8000/auth/register \
  -d "username=alice" -d "email=alice@mail.com" -d "password=secret"

curl -X POST http://127.0.0.1:8000/auth/login \
  -d "username=alice" -d "password=secret" | jq .
  ```


### 5.2. Создание хакатона

TOKEN=<твой_JWT> curl -X POST http://127.0.0.1:8000/hackathons \ -H "Authorization: Bearer $TOKEN" \ -H "Content-Type: application/json" \ -d '{"title":"AI-Challenge","description":"Машинное обучение","start_date":"2025-06-10","end_date":"2025-06-12"}' ```

5.3. Формирование команды

curl -X POST http://127.0.0.1:8000/teams \ -H "Authorization: Bearer $TOKEN" \ -H "Content-Type: application/json" \ -d '{"name":"DreamTeam","hackathon_id":1,"members":[1,2,3]}'

5.4. Отправка решения

curl -X POST http://127.0.0.1:8000/submissions \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"user_id":1,"team_id":1,"hackathon_id":1,"problem_id":2,"result":"accepted"}'
  ```

## 6. Миграции и деплой

При изменении моделей запускайте:

alembic revision --autogenerate -m "описание изменений" alembic upgrade head


Для очистки БД вручную можете сбросить схему:

DROP SCHEMA public CASCADE; CREATE SCHEMA public; ```
